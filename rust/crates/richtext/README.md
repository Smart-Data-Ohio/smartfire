# Smartfire message content

The reference is the Rails app in this repository. Markdown and legacy Action Text share
this crate's Nokogiri-compatible DOM and Loofah-compatible sanitizer; a separate Markdown
crate would duplicate those contracts and their round trips.

## Application inputs

- `markdown::render(source, mentions, icons)` accepts exact Markdown source and rejects more
  than 50,000 Unicode characters. `MentionResolver` returns only a unique active current-room
  member with an exact name. The provided `[RoomMember]` implementation enforces uniqueness
  and activity; pass only members of the current room. A closure can instead supply a
  preloaded, database-resolved lookup. SGIDs come from the application's Rails-compatible signer.
- `IconCatalog` takes brand aliases and their digested URLs, plus workspace icons. Its fallback
  Unicode table contains all 1,913 gemoji 4.1.0 aliases, generated by Ruby. Brand entries win over
  custom entries, which win over emoji. Icon URLs are trusted application inputs, as in `Icons`.
- `text_message_presentation(body, markdown, forwarded_markdown, context, icons, asset_host)`
  selects the helper's text branch. Forwarded Markdown uses the same sanitizer as Markdown.
  Attachment-only messages and sounds belong to their respective controller presenters.
- `markdown::sanitize_presentation` repoints icon sources, validates avatar routes and asset hosts,
  and sets in-app Turbo attributes. Evaluate any Rails-style asset-host Proc at
  `/users/x/avatar` before passing its string result.
- `editable_markdown_source(body, source, context)` preserves non-null source verbatim, otherwise
  runs `LegacyMarkdown`. `editable_value` retains its old signature for presenter compatibility,
  but now returns Markdown textarea source. `legacy_markdown::non_mention_attachments` supplies
  the legacy attachment snapshot needed when edits replace their body.
- `AttachableResolver::embed_image_path` supplies the signed `/embeds/image/...` URL. Its default
  fails closed instead of loading an external image. `twitter_post_exists_for_url` tells the
  legacy partial whether a first-class Twitter card replaces its OpenGraph card.
- `AttachableResolver::mention_avatar_html` supplies bot brand/custom/Unicode avatar markup;
  its default renders the normal user avatar. Supply trusted server-generated markup.
- `AttachableResolver::preloaded_user_for_sgid` supplies request-scoped cached users by the
  unverified payload GID, matching the fork. Without a cache hit, Action Text uses its normal
  signature checks and the attachment renderer retains its User-only expired-signature fallback.

## Parser version

Comrak is pinned to **0.54.0**, the exact version in [Commonmarker 2.10.0's Cargo.lock](https://github.com/gjtorikian/commonmarker/blob/v2.10.0/Cargo.lock).
The option set follows `Commonmarker::Config::OPTIONS` plus `Message::Markdown`'s overrides:
unsafe/raw HTML off, GFM table/tasklist/strikethrough/autolink/tagfilter on, shortcode extension
off, no syntax-highlighter plugin, soft breaks, code language classes, no header IDs. The gem's
escaped-character-span default is reproduced before sanitization.

The vendored html5ever also reproduces Nokogiri 1.19.4 Gumbo's adoption-agency stack behavior.
The Ruby-generated `tests/markdown/parser.json` regression explains why this compatibility change
is required; it is not a serializer rewrite or a corpus normalization.

## Verification

From `rust/`:

```sh
reference-tools/markdown/run.sh
reference-tools/richtext/run.sh
mise exec rust@1.98.1 -- cargo test -j 6 -p campfire_richtext -- --nocapture
mise exec rust@1.98.1 -- cargo clippy -j 6 -p campfire_richtext --all-targets -- -D warnings
```

The new corpus compares 4,184 cases byte-for-byte without normalization: the complete 652
CommonMark and 671 GFM examples, all gemoji aliases, brand aliases, normal/bot and preloaded mention contexts, source-length
boundaries, attack inputs, presentation image/link rules, fixtures, and legacy editing. Four
additional source-limit vectors come from Rails model validation, and the parser regression comes
from Nokogiri. The independent XSS suite checks 768 outputs and detects planted defects.

The inherited legacy corpus now comes from our fork (1,047 cases). Its historical test still
accounts for **pre-existing security differences**: the port never inserts auto-links into
attributes and strips `name` attributes. It prints the raw byte-difference count and every affected
case, before that historical comparison. Set `RICHTEXT_RAW_DIFF_OUTPUT=/tmp/ws5-diffs.json` to export
the raw audit. Exact legacy parity for these cases requires a lead decision or a Rails fix; these
exceptions are not part of the new Markdown corpus's zero-difference result.
