# Smartfire mail

This crate owns the reference's `app/mailboxes/**`, `app/mailers/**`, raw-email records,
mail templates and SMTP delivery. It uses the existing disk service and writes the Rails
schema without migrations. Its in-process rate counter follows decision 3.

WS9 can enqueue notifications inside its triggering write:

```rust,ignore
if app.mail.config.security_configured() {
    campfire_mail::jobs::new_sign_in_alert_later(tx, activity_item_id);
}
if app.mail.config.two_factor_configured() {
    campfire_mail::jobs::lockout_notice_later(tx, user_id);
}
```

The app adapter resolves records when performing the durable delivery job. A revoked
session skips mail. SMTP defaults match `config/initializers/outbound_mail.rb`; the two
mailers intentionally preserve their different Rails From defaults.

Inbound acceptance atomically saves the record, blob attachment and routing job. Status
updates schedule 30-day incineration, which checks Rails' end-of-day eligibility and emits
a purge job. Duplicate `(message_id, message_checksum)` acceptance does not post again.
Routing replays return `Routed::AlreadyRouted` for a delivered or bounced record. Failed
attempts remain eligible to retry; transient errors restore Pending without scheduling
incineration. The serialized writer
rechecks status in the transaction that creates the post and commits the terminal status,
so concurrent routes and an error after commit cannot create another post or enqueue.

MIME parts use an explicit parsing stack. The reference Mail 2.9.1 gem has no numeric
depth cap and splits bodies lazily; its 2,000-part no-room fixture bounces without a post.
The routing parser reads only the headers for non-room recipients, so the reference's
324 KB, 4,000-level bounce fixture performs zero MIME-boundary scans. Body parsing uses
an explicit stack when room mail needs it. The fixture was checked against Rails before
Rails was removed. Authentication follows Ruby's ASCII regex whitespace
and String#strip sets; ActiveSupport presence remains Unicode-aware where Rails uses it.

`Renderer::render` supplies the shared room-aware Markdown/mention renderer from WS5/WS8.
`mail::State::install_renderer` installs it in the app. Until installed, valid room mail remains
pending and its durable job reschedules without consuming retry attempts. Bounces and invalid
tokens complete without a renderer. The running app installs its shared AppRichText adapter at boot; a real durable routing test
compares the resulting source, canonical body, plain text and creator with RoomMailbox.
The crate's integration tests inject a simple rendering function and test the actual Message
API, callbacks, SQLite transactions and files, not Markdown rendering.

`MessageCreated` is an `Event::Job` committed with the message. The app handler processes
its attachment and broadcasts using the existing hub. WS11 installs `install_fanout` for
`Message::BotWebhookFanout`. Until installed, webhook fanout is partial.

The local mail layout copies the Rails ERB layout. WS6 owns layouts and should reconcile this
copy on integration. Eight controller/view tests belong to WS8b; token rotation is available
as `Room::regenerate_inbound_email_token` here.

The oracle was generated by our Ruby mailboxes and mailers in the Rails app's image; it's
frozen now that Rails is gone (the generator is in the git history). Message IDs and MIME
boundaries are injected before serialization, rather than masking serialized output. Dates
are fixed. Tests compare the whole MIME bytes, plus authentication and HTML text corpora.
The oracle includes 34 full messages covering display-name specials, tabs, quotes, commas,
Unicode and long encoded words, plus 579 authentication cases and whitespace coercions.
Basic-auth vectors store credential parts and mutation recipes; tests construct headers
at runtime to keep encoded authorization headers out of source fixtures.
The corpus includes sanitized structures from 32 public real-email HTML parts and two
archived Authentication-Results fields; their provenance and redaction rules are in the
git history, under `reference-tools/mail/corpus/`. Modern mail-client coverage remains limited.

Production MIME depth was recorded against the Rails app (`vectors/mail/mime-depth.json`, frozen).
The recorder submitted an authenticated relay request, then ran the production `resque-pool`
command against a cloned seed, and recorded actual statuses, post sources and exceptions.
Per the "cutoff errs low" decision, routing's limit is the last successful production depth
minus at least 10%. Greater depth produces a terminal bounce with no post or staged files.
