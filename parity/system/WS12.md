# WS12 named system assertions

The seven `ws12_browser_c221`–`c227_original_named_system_assertions` tests use
the production router, forms, saved reloads and Cable in real Chromium. They are
explicitly ignored by ordinary Cargo/nextest runs, like
`huddle_system_cases_in_real_browser` (`controllers/rooms/system_browser_tests.rs`)
and the WS8bm `ws8bm_browser_host_without_jobs` fixture. The gating toolchain
container intentionally does not supply Node or a browser; these assertions run
through the external browser harness, rather than that gate.

From the repository root:

```sh
parity/system/ws12 > .scratch/ws12-browser.log 2>&1
```

Create `.scratch` before redirecting. Requirements are Cargo/Rust from the pinned
toolchain, host Node with native TypeScript support, Docker, and the validated
`default`, `first_run` and `agents_ui` seeds (see `../seeds/README.md`). The harness
builds the image from `Dockerfile.playwright`, `package.json` and `package-lock.json`
if it is missing, then runs all seven tests with `--ignored --show-output` and one
test thread. Each test runs at 10 and 100 members and asserts flat SELECT counts.
Chromium is inside the pinned, network-isolated container, with the production
router exposed through a private Unix forwarder. Missing dependencies or failed
browser assertions fail the harness; there is no successful skip path. Keep the
usual Cargo/rustc throttle and native media environment when running locally.
Temporary sockets use `$XDG_CACHE_HOME/rust-port/ws12` (or `$HOME/.cache/rust-port/ws12`)
to stay below Unix socket path limits in nested worktrees; `WS12_BROWSER_SCRATCH`
can select another short directory.

For Rails, `reference-tools/users/ws12_browser_remaining.py` replays the same
committed Chromium driver against the pinned Rails server. The companion Ruby
oracle emits the setup vectors in `vectors/ws12_browser_remaining.json`.

The reconciliation and mutation catalogs mark these seven tests `run_ignored`
and name this harness. Producer replay honors that marker by passing `--ignored`;
its executed-test guard still rejects any skipped assertion. Reconciliation
requires a dedicated **passing** browser receipt in addition to the workspace
receipt:

```sh
python3 reference-tools/users/verify_ws12_reconciliation.py \
  --test-log .scratch/workspace.log --browser-test-log .scratch/ws12-browser.log
```

Default-run `ignored` lines never count as coverage. The dedicated receipt retains
the real-browser traces and the ordinary `test ... ok` lines used by the checker.
