WS11 owner APIs for WS11-UI (Rails pin d7c7de92)

- `NewUser.icon_name: Option<String>` and `UserChanges.icon_name: Option<Option<String>>` use the Rails normalizer and changed-field validator. `User.icon_name` exposes the stored name. `User::set_icon_name(tx, Option<&str>)` uses the same update path. A changed icon touches updated_at, invalidating the fresh avatar URL; an equivalent normalized assignment does not.
- `User::create_bot_with_attributes(tx, NewUser, webhook_url)` accepts the icon on bot creation and forces bot role plus a newly generated digest. Existing `create_bot(tx, name, webhook_url)` delegates to it unchanged. Unknown icons return `Error::RecordInvalid` with `icon_name: is not a known icon`, for the UI owner's 422 handling. No bot row is inserted. Brand aliases, gemoji aliases and live workspace names resolve. A persisted unknown icon is validated only if changed, matching Rails.
- `models::user::icon::{normalize_name, normalize_input, validate}` are public. `normalize_input` includes AR string casting (true -> t; false -> f). HTTP owners must apply their scalar strong-parameter filter first; arrays and objects are unpermitted.
- `AgentChanges` adds `daily_message_cap_before_type_cast`, `daily_board_post_cap_before_type_cast`, and `daily_external_action_cap_before_type_cast`, each `Option<serde_json::Value>`. None means absent; Some(Value::Null) explicitly clears. A raw input takes precedence over its existing typed cap field. Existing typed fields and service signatures remain unchanged.
- `changes.budget_cap_input(field)` supplies `before_type_cast`, cast `value` and Rails numericality `errors`, without writing. Retain/clone changes before the consuming update to redisplay the submitted value after rejection. `agent.validate_changes(conn, changes.clone())` validates the complete prospective record without writes, before saving the bot. `agent.update(tx, changes)` repeats those checks. Values beyond SQLite's signed 64-bit storage range can validate in Rails but raise on persistence; they produce a storage error here and retain their raw/cast form values.
- `agent.webhook_signing_secret(conn, &ArEncryption)` is read-only, returning Result<Option<String>>. It preserves nil versus empty/whitespace and never calls ensure, rotates, generates or touches updated_at. UI legacy-secret fallback is nil-only, owned by WS11-UI.
